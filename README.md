# AI-Based Network Intrusion Detection Using K-Means and Naive Bayes

## Problem and Objective

This college mini project studies how a five-dimensional, centroid-distance representation can be used to classify network traffic. It compares Gaussian Naive Bayes trained on those distance features with a Naive Bayes baseline trained on the preprocessed original features, plus a small Decision Tree comparison.

## Dataset

Use the NSL-KDD `KDDTrain+.txt` and `KDDTest+.txt` files. Place both files directly in `data/`; see [data/README.md](data/README.md) for file format and sourcing details. Dataset records must be the standard comma-separated format with 41 features followed by the attack name and, optionally, difficulty score. The project does not download or generate data. Training stops with a direct error if the required files are absent.

Attack labels are mapped to Normal, DoS, Probe, R2L, or U2R using the mapping in `src/data.py`. `httptunnel` is assigned to R2L, following the standard NSL-KDD grouping; unknown names raise an error and are not silently assigned. K-Means cluster IDs are arbitrary and do not represent these semantic classes.

## Methodology

1. Load the train and test files with the standard 41 NSL-KDD feature names.
2. One-hot encode `protocol_type`, `service`, and `flag`; Min-Max scale numeric features. Fit both transformations on training data only and reuse them on test data.
3. Fit K-Means with K=5 on the preprocessed training representation and record its cluster sizes.
4. Transform every record into its Euclidean distance to each of the five learned centroids.
5. Train Gaussian Naive Bayes on the five distances. Also train the original-feature Naive Bayes baseline and a depth-limited Decision Tree comparison.
6. Evaluate on `KDDTest+` with accuracy, precision, recall, F1, confusion matrix, per-class report, attack detection rate, and normal-traffic false-positive rate.

This is an implementation of the reference paper's general methodology, not a reproduction of its reported experiment. Metrics shown by this project are generated by running this code on the supplied dataset.

## Installation and Run

From the project directory (PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Download the two NSL-KDD files separately and place them in `data/`, then run:

```powershell
python train.py
streamlit run app.py
```

Open `notebooks/intrusion_detection_analysis.ipynb` in VS Code to run the EDA and analysis narrative. The notebook uses the same project modules and needs the same dataset files.

## Expected Outputs

`train.py` saves fitted preprocessing, K-Means, and classifier artifacts under `models/`. Under `outputs/` it writes the model comparison CSV, detailed metrics JSON, cluster-size CSV, and one confusion-matrix image per evaluated model. These files are produced by an actual run; no performance values are hard-coded.

The Streamlit dashboard contains Overview, Data Analysis, K-Means/PCA, Model Evaluation, and CSV Prediction sections. Prediction accepts a CSV with the 41 named features or headerless NSL-KDD records.

## Metrics

Accuracy is the fraction of test records classified correctly. Precision, recall, and F1 are reported as macro and weighted summaries and per class. Attack detection rate is the fraction of actual attack records predicted as any attack. False-positive rate is the fraction of actual Normal records predicted as an attack.

## Limitations

Results depend on the provided NSL-KDD files and the selected preprocessing and model settings. One-hot encoded features and Euclidean distance do not make categorical values intrinsically ordinal or meaningful in geometric space. K-Means optimizes geometric partitions rather than attack classes, and the five clusters are not guaranteed to correspond one-to-one with the five labels. The test set may contain attack types or distributions unlike future traffic; these results should not be interpreted as production detection performance.
